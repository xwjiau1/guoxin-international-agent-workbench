# Git、产物与发布边界

- 修改前查看分支、工作区和差异，保护用户已有修改；发现重叠先协调。当前基线分支为 main，但不据此假定其他环境分支约定。
- 提交、分支和 PR 沿用仓库现有约定并关联 change/task ID；只在用户要求时提交或推送。逐文件审查暂存差异，不混入他人修改、密钥、`.env`、缓存、备份、工作树或个人配置。
- 未获授权不强推、改写共享历史、破坏性 reset/clean、删除未知文件、合并、公开发布或发送外部消息；不绕过检查和权限。
- 多代理写入前读 `docs/development/git-workspaces.md`。整合冲突以当前需求和契约为依据，解决后重验。
- 源码、Spec、契约、测试与必要锁文件一起维护。prebuilt 只收集产物不会编译；源码变化后必须重新生成 JAR/dist 并核对镜像/容器哈希，不能把旧产物当新版本。
- 发布前按版本门禁准备备份、迁移和回滚方案，部署对应产物并做 smoke/live 验收，再更新发布清单、验证记录和 HANDOFF。备份生成不等于恢复已验证，Checkpoint/镜像回滚不等于业务撤销。
