# 测试与证据门禁

- 行为变化先定义验收。Bug 优先建立修前失败、修后通过的回归；重构先建立行为基线。不能自动化时记录环境、精确步骤和修前/修后证据。
- 按影响运行仓库已有检查，覆盖正常、边界、错误、权限、防重和恢复分支。未设覆盖率门槛时不擅自要求全仓 80%，也不删断言或改正确预期凑通过。
- 六类证据必须分开命名和计数：Agent 离线测试；真实 PostgreSQL 业务测试；Boot HTTP + PostgreSQL 集成；显式真实 Qwen；API 桩浏览器；真实 Docker/Qwen 浏览器。API 桩不能替代真实后端，test 模型不能替代 Qwen，单个模型用例不能代表全部意图稳定。
- 默认 Maven verify 中真实 Qwen 用例可跳过；PG_TEST_URL 未配置时数据库用例可跳过。必须查看 Surefire/Playwright 汇总，gated、skipped、not_run 不得写成通过，重复执行不得累计成独立覆盖。
- 真实 Qwen 测试只按文档显式启用并说明 API 用量；真实浏览器写入只针对 local-demo 或隔离测试数据，不得向真实企业审批系统执行演示操作。
- 数据库测试使用自己的随机 schema/测试夹具，只清理自己创建的对象；不得通过清空演示库、删除卷或绕过在途业务约束追求绿灯。
- 接口变化补生产者/消费者契约验证；UI 变化检查关键交互和失效状态；Prompt/Skill/Schema 变化补旧任务、确认失效和升级兼容验证。
- 部署相关变更需核对源码版本、JAR/dist 哈希、镜像和容器内产物。旧镜像或旧 prebuilt 产物通过不能证明新源码已部署。
- 分别报告 pass/fail/blocked/skipped/not_run 及实际命令、环境和证据。存量失败须有基线证据；相关失败未解决不得标完成。
- 纯文档/格式变更不强制新增业务测试，但应执行链接、差异和适用的一致性检查，并明确未重跑业务测试。
