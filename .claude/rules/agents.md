# Agent 协作与文件所有权

- 默认由主代理完成；仅在用户授权、运行环境允许且任务独立可验证时委派，不为形式创建团队。
- 编码派工前先稳定任务 ID、Spec/验收、输入契约、前置依赖、允许/禁止路径、验证命令和完成条件，并读 `docs/development/agent-team.md`。
- 多 Agent 开发分配独立目录/文件所有权；同一文件默认只有一个写入者。共享 domain/application 端口、OpenAPI、Schema 或 Workflow 变更先协调，再并行生产者与消费者。
- 写入代理使用独立 worktree/分支和个人产出区；无法隔离时串行。worktree 不隔离数据库、端口、Docker 容器、模型用量或测试数据，不得让多个执行器操作同一可变业务环境。
- 工作代理只修改派工范围，发现依赖、需求或契约变化交回主代理，不自行扩大范围。主代理复核实际差异和证据后再整合，整合后重验，不仅凭代理自述判完成。
- 执行中相关 Bug 记为父任务的 `T-xxx.B-01`；无关问题只登记和报告，不顺手扩展修复。
- 模型按任务难度、风险、成本和实际可用性选择，默认继承，不编造模型 ID。安全、迁移和架构关键判断不得仅交给低能力代理独立决定。
