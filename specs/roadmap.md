# 后续版本路线

更新：2026-11-12。保留用户确认的顺序：Agent主体 → 接口发布与能力封装 → RAG与评测 → 完整业务体系 → 真实系统试点。以下是计划，不代表已实现或已验证；每版先建立独立spec/plan/tasks后实施。

## V0.1 主体闭环基线

范围见[v0.1 spec](v0.1/spec.md)。先完成真实浏览器链路、产物部署一致性与交接门禁。已知简化项不能通过把“计划”改成“完成”消除；权限、确认和幂等缺陷优先修复。

## V0.2 接口发布与业务能力治理

目标：将当前代码绑定的模拟能力扩展为有契约、可验证的接口/工具/Skill/Workflow发布流程。

- 完整接口目录、参数/返回Schema、业务错误、身份和幂等约定；发布前可调用验证。
- 结合OpenAPI与表单/流程元数据生成Skill草稿，人工或规则校验后发布；不从接口字段猜审批规则。
- Skill/Prompt/Workflow/Schema不可变版本、引用与旧任务兼容；收敛当前manifest、代码模板与说明文件的多来源。
- 四类单据公共元数据及更多办理流程；完善任务切换、失败重试选择和管理入口。
- 针对已登记的漂移补必要迁移、契约检查和恢复专项；先明确需求，不强行引入复杂调度平台。

验收：新增一个支持的单据场景主要扩展能力配置、元数据和适配器，不重写主体；越权、确认、防重不变量仍成立。对真实API的模拟切换需有契约回归。

## V0.3 RAG治理、问答与评测复现

目标：真实实现BGE-M3 + Qdrant + bge-reranker-v2-m3，生成模型继续Qwen API。

- 知识导入、解析、条款切片、版本/生效时间/权限、向量索引、发布与下线。
- 权限过滤检索、重排、证据引用、无证据/冲突回答、FAQ及badcase归因反哺。
- 明确Embedding与Rerank独立推理服务、配置和故障策略；不能用其他模型标称相同复现。
- 固定开发集/保留测试集，保留数据与检索/Prompt/模型版本；记录Hit@5、Recall@5、MRR、答案与引用、权限及延迟。
- 优化前后使用同一评测口径，不填入简历原有百分比，不保证零泄露超出实际测试集。

验收：可重跑的入库与问答链路、真实引用、权限专项和回归报告；对各阶段优化有真实证据。前置设计见[05 RAG](../docs/05-RAG与后续扩展.md)。

## V0.4 OKR与完整业务页面

- 本人Objective/KR维护、进展记录、周期统计与风险提示；公式及权重由业务规则明确配置，统计不由模型猜测。
- 证照台账、申请详情、审批进度、借出/归还交接、待办中心、员工和流程分配体系。
- 页面和对话使用同一业务应用层与权限；审批通过、实际交接分别维护。

验收：对话与页面修改一致、版本冲突可处理、所有数据范围正确。角色和业务字段在该版规格中细化，不在本版文档提前宣称可用。

## V0.5 真实系统试点

- 接入企业认证和真实低代码底座，替换模拟业务适配器，保留原主体协议。
- 按真实业务系统定义确认、幂等、结果查询和权限映射；不假设任何外部接口天然支持安全重放。
- 完成迁移、审计、备份恢复、容量和故障演练；确定单实例是否仍满足需求。
- 如需私有化生成模型，单独立项验证；当前不纳入已授权首版部署范围。

验收：模拟回归用例在真实适配环境仍成立，并补齐企业实际规则和接入验收。不得直接把演示账号、默认密码或模拟制度用于正式环境。

## 跨版本原则

每版保持[v0.1不变量](v0.1/spec.md)及[AGENTS](../AGENTS.md)的数据/权限约束；变更编号、验收、实现、证据和部署信息形成闭环。功能优先级可由用户后续调整，但不能隐式扩大业务授权或把未完成项移出状态记录。
