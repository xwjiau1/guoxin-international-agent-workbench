# Git 与工作区隔离

> 触发：并行编码、创建/整合 worktree 或跨代理交接。单代理在当前项目工作不强制创建 worktree；只有用户明确要求或项目指令授权时才使用平台自动 worktree。

## 绑定与隔离

- 主项目区用于整合，写入代理绑定独立 Git worktree、分支和 `.agent-work/<agent-id>/<task-id>/` 个人产出区；在派工中记录绝对路径、基础提交和文件所有权。
- 手工内嵌工作树可放 `.worktrees/`，创建前确认已被 `.gitignore` 忽略；自动工作树登记实际路径，不假定一致。
- 同一文件单一写入者。共享 domain/application 端口、OpenAPI、Schema 或 Workflow 先由 Lead 稳定契约，再分独立目录实施。
- worktree 只隔离文件和 Git 分支，不是进程/安全沙箱。不得让多个代理同时控制同一 Compose 项目、数据库卷、端口、测试 schema、模型用量或业务记录。
- 本项目 Compose 项目名固定 `guoxin-assistant`，改变它会创建另一组容器/卷，不能把新空库当隔离测试或把原库判为丢失。并行环境须先单独设计，不能擅自改名启动。
- worktree 不可用则串行写入，不能用普通复制目录冒充版本隔离。清理前确认成果已保留且无未提交修改。

## 整合

1. 开始前检查分支、状态、差异和基础提交，保护用户已有工作。
2. 提交保持单一目的并关联 change/task ID；逐文件暂存和审查，不提交秘密、个人配置、缓存、备份或构建产物（仓库明确跟踪的发布清单除外）。
3. 主代理核对实际文件、Spec 和分层测试后整合；冲突按当前需求/契约解决，整合后重验。
4. 未经用户明确要求不提交、不推送、不合并、不发布。应用部署还需产物/镜像一致性、备份、迁移和回滚证据。
