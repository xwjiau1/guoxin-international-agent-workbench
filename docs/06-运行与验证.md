# 06 运行与验证

环境决策（2026-11-11）：按用户要求，PostgreSQL、后端和前端统一使用 Docker Compose。此前试验的便携 PostgreSQL 已停止，不再作为启动依赖；未注册 Windows 服务，也未更改系统 PATH/JAVA_HOME。

## 1. 安装与启动

本机需要 Docker Desktop，使用 Linux containers / WSL 2 backend。安装后确认 Docker Desktop 显示引擎运行，执行 `docker info` 和 `docker compose version`。若 WSL 安装提示管理员或重启，需要用户完成系统操作；项目脚本不自动重启。

本机 AppData 有路径重定向，Docker 默认配置文件的原子重命名会报跨盘错误。已通过 `scripts/docker-env.ps1` 为当前进程及其子进程设置 D:\GuoxinAssistantRuntime\Docker 下的配置、缓存与临时目录解决，不修改全局环境。当前机器执行 Docker 命令前先运行 `. .\scripts\docker-env.ps1`；start.ps1 已自动加载。重新启动 Docker Desktop 也需在加载该环境的 PowerShell 中启动，避免使用默认环境重复触发错误。

完整日常维护、代码迭代、备份恢复和部署回滚步骤见[运维与部署手册](运维与部署手册.md)，其他Agent从[接管入口](../HANDOFF.md)进入。

官方说明：[Windows 安装](https://docs.docker.com/desktop/setup/install/windows-install/)、[WSL 2 backend](https://docs.docker.com/desktop/features/wsl/)。

在项目根目录按需复制 `.env.example` 为 `.env` 并填写模型配置。若当前终端已有 QWEN_API_KEY 或 DASHSCOPE_API_KEY，可直接继承，不必另存密钥。不要执行或分享会展开 Key 的 `docker compose config` 输出；检查语法使用 `docker compose config --quiet`。

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

也可以运行 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`。脚本只管理 Docker Compose，不启动本机数据库或 Java/Node 服务。

若已有通过验证的后端fat JAR和前端dist，可使用较小的运行时镜像，省去在容器中重新下载构建工具：

```powershell
. .\scripts\docker-env.ps1
powershell -ExecutionPolicy Bypass -File scripts/prepare-prebuilt.ps1
docker compose -f compose.yaml -f compose.prebuilt.yaml up -d --build
```

同等的一键入口为 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Prebuilt`，包含隔离环境和Docker引擎就绪检查。

该方式只复用编译产物，应用依然在Docker中运行；修改源码后必须先重新构建产物或使用默认源码构建方式。

访问工作台：http://localhost:5173 。演示账号 DEMO001（张晨）、DEMO002（李敏）、DEMO003（王宁），密码均为 Demo@123。界面及固定账号仅用于模拟环境。

端口仅绑定本机：5173 工作台，8080 后端，55432 PostgreSQL。数据库数据在 Compose 的 postgres-data 命名卷，使用 Linux 容器文件系统，避免 Windows 中文路径和文件重命名兼容问题。

首次启动数据库为空时创建演示资料；再次启动保留会话、草稿、审批状态及追踪。改变数据库密码后，已初始化卷不会自动改用户密码，需按数据库管理流程修改，不能假设环境变量会重置旧卷。

## 3. 验证命令

```powershell
# 在容器中运行后端测试，真实 PostgreSQL 由 Compose 提供
docker compose --profile verify run --rm verify

# 显式调用真实模型验证 Agent 只读工具循环（会产生 API 用量）
docker compose --profile verify run --rm verify mvn -s ../.mvn/settings.xml -B -ntp -pl assistant-agent -am -Dtest=QwenLiveTest -Dsurefire.failIfNoSpecifiedTests=false -Dagent.live-test=true test

# 查看运行情况；不要公开包含个人信息的完整业务日志
docker compose logs --tail 100 backend
docker compose ps
```

数据库测试每次创建隔离 schema；业务测试完成清理该 schema，不删除演示环境表。Boot 集成测试使用单独随机 schema，保留失败现场供定位；只有测试夹具可清理其自己创建的 schema。

frontend 的生产构建在 frontend 镜像内执行。浏览器测试连接已运行的 Docker 工作台，不再自动启动本机 Vite；API 桩测试与真实后端测试需要分别报告。

## 4. 调试与停止

```powershell
docker compose stop
docker compose start
docker compose down
```

`down` 默认保留命名卷；正常维护不要加 `-v`。升级代码后重新执行 `docker compose up -d --build`。首次拉取镜像或 Maven/npm 依赖可能耗时，安装失败需要查看具体网络或构建错误，不把前端能打开等同于后台闭环可用。

首版单 JVM 执行器通过 PostgreSQL advisory lock 防止同数据库出现两个任务执行器。暂不支持横向扩容；停止旧后端后再启动新实例。任务命令持久化，启动时恢复上次未结束命令，已发出的业务写入通过幂等回执核实。

需要调试源码时，保持数据库与应用在 Docker 内，开启仅本机可访问的 JVM 调试端口：

```powershell
docker compose -f compose.yaml -f deploy/compose.debug.yaml up -d --build
```

IDE 打开 backend/pom.xml 并选择 Java 21，配置 Remote JVM Debug 连接 localhost:5005。推荐先在 RunCoordinator.execute、WorkflowAgentRuntime.run、MockBusinessService.invoke 设置断点，理解请求、图节点和业务工具的调用关系。结束调试后使用基础 compose.yaml 重建后端以关闭调试端口。

## 5. 实现与设计的对应

- gxa_* 表保存会话、命令、任务快照、消息、组件及执行事件。
- gx_biz_* 表是模拟业务底座，独立保存员工、证照、草稿、单据、流程、待办、审批和幂等回执。
- 确认快照、字段来源、能力版本与逐项执行结果保存在任务 JSON；首版未拆成独立配置管理后台。
- LangGraph4j 真实图检查点按 taskId:runId 保存本轮节点状态；跨轮多轮恢复由持久化任务快照实现，不能把检查点回放等同于业务回滚。
- RAG/知识治理及完整 OKR 属于后续版本，首版不宣称已接知识库或已完成评测指标。
