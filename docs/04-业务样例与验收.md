# 04 业务样例与验收

## 1. 演示组织与数据

所有名字、单据和制度均为虚构演示数据，界面注明“模拟业务环境”。

| 员工 | 编号 | 部门 | 场景 |
| --- | --- | --- | --- |
| 张晨 | DEMO001 | 综合管理部 | 默认登录用户，拥有证照和本人待办 |
| 李敏 | DEMO002 | 综合管理部 | 张晨的模拟申请审批处理人，也持有本人数据 |
| 王宁 | DEMO003 | 财务部 | 其他申请人，部分待办分配给张晨，验证申请人/处理人区别 |

每人有独立 session、会话、草稿和证照。模拟单级流程：张晨提交→李敏待办；李敏提交→张晨待办；王宁部分申请→张晨待办。上述是演示路由配置，不是自动从员工关系推导的企业制度。

固定演示基准时间为 2026-11-11 Asia/Shanghai，仅在验收时使用可注入时钟；正常运行读取真实当前时间。准备 12 条待办：张晨处理 8 条（4 出差、2 报销、1 因私出境、1 因私证照办理），李敏处理 4 条。张晨的 4 条出差待办中 3 条到达于 2026 年 10 月，1 条于 11 月；供日期筛选验收。

证照数据：张晨一份保管中的有效护照，一份已借出的港澳通行证；李敏拥有独立护照。真实原始号码不进入对话，演示仅展示脱敏编号。已借出证照借用返回业务冲突，不通过重复重试解决。

## 2. 单据类型与首版深度

| formType | 名称 | V0.1 支持 |
| --- | --- | --- |
| TRAVEL_APPLICATION | 出差申请 | 待办查询、统计、同意/驳回 |
| REIMBURSEMENT | 报销单 | 待办查询、统计、同意/驳回 |
| PRIVATE_OVERSEAS | 因私出国（境）审批表 | 待办查询、统计、同意/驳回 |
| PRIVATE_CREDENTIAL | 因私证照办理申请表 | 办理/借用模式的字段收集、草稿、提交；待办审核 |

演示证照借用映射为 PRIVATE_CREDENTIAL 中的 BORROW 模式；这只是模拟元数据建模，不认定真实企业一定使用同一张表。V0.2 可通过适配器拆成独立借用单据。

因私出境审批和证照申请暂为独立单据；若用户同时要求两项，拆成两个任务并依次办理，不默认一次确认提交多张相关表。后续通过显式 Workflow 配置依赖关系。

## 3. 因私证照元数据 v1

| 字段 | 类型/来源 | 必填与规则 |
| --- | --- | --- |
| applicantId/name/department | 后台本人资料，只读 | 服务端确定，不接受前端或模型覆盖 |
| requestMode | 枚举 BORROW/APPLY | 提交必填，按意图识别，不明确则询问 |
| credentialType | 枚举 PASSPORT/HK_MACAO_PERMIT | 提交必填，口语别名映射到合法值 |
| credentialId | 本人证照选择 | BORROW 必填；多份符合时让用户选 |
| destination | 文本 | 提交必填，不能由系统猜测 |
| departureDate | 日期 | 提交必填，不能早于当前日期 |
| arrivalBackDate | 日期 | 提交必填，不能早于出发日期 |
| returnDate | 日期 | BORROW 必填，不早于返程日期 |
| purpose | 文本 | 提交必填，2–500 字 |
| applicationReason | 文本 | APPLY 必填，2–500 字 |
| remark | 文本 | 选填，最多 1000 字 |

以上为演示规则，不代表正式办理所需资料齐备。首版不要求文件附件。工作人员联系电话等可从本人信息带出但不作为新增必填项。

保存草稿允许提交必填项为空，已填日期/枚举仍需合法。没有护照而用户要借护照时，提示没有可借证照并询问是否转为办理申请，不能自行改变申请类型。

审批动作只支持 APPROVE/REJECT；REJECT 演示规则要求 2–500 字意见；“退回补充”若真实流程另有动作，V0.1 不自动等同于驳回，提示当前支持的动作。

## 4. 证照借用交互脚本

1. 用户：“下个月去日本旅游，帮我借护照。”
2. 系统查询本人资料、表单元数据和本人护照；提取 destination=日本、purpose=旅游、requestMode=BORROW。展示已带出的本人资料，追问具体出行、返程和归还日期。
3. 用户：“12 月 15 日出发，20 日回来，21 日还。”以验收时钟解释为 2026-12-15/20/21，生成预览，显示完整日期。
4. 用户：“先保存草稿。”保存草稿，返回编号；任务为 DRAFT_SAVED，无流程生成。
5. 刷新或重启后用户：“继续刚才借护照的申请，改成 22 日归还。”恢复草稿；同月含义明确时更新，不明确则追问。生成新预览。
6. 用户确认预览，后端校验→生成单据和审批流程→李敏待办。返回单据号、流程号、IN_APPROVAL。
7. 用户：“审批到哪了？”查询真实模拟流程状态。李敏通过本人 session 审核后，再次查询显示 APPROVED；不自动宣称已领取证照。

## 5. 待办审核交互脚本

1. 用户：“统计上个月我的出差待办。”过滤 assignee=张晨、type=TRAVEL_APPLICATION、status=PENDING、arrivedAt ∈ [2026-10-01T00:00+08:00,2026-11-01T00:00+08:00)，返回 3 条，明确日期字段。
2. 用户：“只留去上海的。”重新筛选，返回命中的组件，统计与明细使用同一过滤对象。
3. 用户：“同意这几条。”形成 APPROVE 预览，用户可排除其中一条，范围调整后重新生成确认。
4. 用户确认，逐项执行并返回结果；无论其他审批人有多少待办，都不纳入本次范围。
5. 用户：“王宁那笔报销金额不对，不同意。”查询候选；有多笔则消歧，提取 REJECT 及意见“金额不对”，发送确认卡片后执行。
6. 用户：“不对，我要看申请日期是上个月的。”这是筛选修正，不能执行驳回。

## 6. 故障注入设计

仅 local-demo/test profile 允许故障计划，通过本地配置或受控测试夹具启用，不暴露给普通员工工具或公共 API。按工具、operationId、attempt 定点注入，一次触发后记账。

| 故障计划 | 模拟行为 | 应观察结果 |
| --- | --- | --- |
| READ_FAIL_ONCE | 第一次查询连接失败 | 记录失败、抖动等待、第二次成功 |
| RATE_LIMIT_ONCE | 首次返回 429 + Retry-After | 按预算等待后恢复，不高频请求 |
| REQUIRED_FIELD | 后台校验发现缺 returnDate | 回到资料收集，保留其余字段 |
| SCHEMA_CHANGED | 提交前元数据升级 | 刷新规则、旧确认失效、生成新预览 |
| COMMIT_THEN_TIMEOUT | 业务事务成功后丢失响应 | UNKNOWN→查回执→成功，数据库只有一张单据 |
| TODO_ALREADY_HANDLED | 预览后另一会话完成一项 | 该项冲突，其余按策略处理，逐项回执 |
| BATCH_ONE_TRANSIENT | 一项首次暂时故障 | 只重试该项，成功项不重做 |
| MODEL_STREAM_INTERRUPTED | 文本或工具参数途中断流 | 不执行残缺参数，重置临时文本，有限恢复 |

## 7. 验收矩阵

| 编号 | 操作 | 必须验证的事实 |
| --- | --- | --- |
| A01 | 真实 Qwen 多轮填单 | 供应方真实请求；资料自动带出；仅追问缺失字段 |
| A02 | 未填完保存草稿 | 草稿落库、未生成审批流程；恢复后内容一致 |
| A03 | 修改归还日期 | 原确认失效；新确认显示更新日期 |
| A04 | 重复点击确认/重发请求 | 只有一个业务单据、流程及操作结果 |
| A05 | 其他用户访问任务/草稿 | 返回 404，不泄露内容 |
| A06 | 查询本人待办 | 返回处理人是本人且申请人可以为他人的任务 |
| A07 | 日期筛选和统计 | 时区、边界、日期字段明确；总数与明细一致 |
| A08 | 勾选和排除再确认 | 只处理最终确认快照内的条目 |
| A09 | 同意/驳回/筛选修正 | 正确区分动作；驳回缺意见则追问 |
| A10 | 网络故障和 429 | attempt、等待和上限可查；不无限重试 |
| A11 | 缺参/非法枚举 | 字段错误引导修正，非系统性重复请求 |
| A12 | 提交成功但响应丢失 | 查回执收敛，不产生第二张单据 |
| A13 | 进程崩溃后恢复 | 未领命令可继续；在途写入先核实 |
| A14 | 批量部分失败 | 成功/失败/失效清晰；重试不重复成功项 |
| A15 | SSE 断线/刷新 | 事件去重、卡片状态恢复、不重发业务操作 |
| A16 | 多标签页同时改任务 | 旧 expectedTaskVersion 返回 409，内容不覆盖 |
| A17 | 插问/暂停/取消 | 原任务可恢复；取消不假称撤销已发生业务 |
| A18 | 很长历史对话 | 摘要后字段/确认/操作事实不丢，工具消息完整 |
| A19 | 追踪查询 | 同一 task 下多 run、节点、工具、重试及业务号串联 |
| A20 | 预算耗尽/模型不可用 | 保存可恢复任务；业务已成功时仍展示真实回执 |

自动化重点是 A04–A16 的数据库、权限、并发和异常行为。真实模型验收覆盖代表性意图、修改和工具选择，不要求每次文字逐字一致。验收记录写明运行环境、依赖、模型配置、用例结果与已知问题；本文件尚未执行任何用例。
