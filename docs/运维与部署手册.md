# 国新国际智能小秘：运维、迭代与部署接管手册

更新时间：2026-11-12。适用于当前 V0.1 仓库。所有命令默认在项目根目录的 PowerShell 执行；应用、数据库始终通过 Docker 运行。本机 Maven/Node 只在 prebuilt 构建或开发测试时使用，不替代容器中的应用服务。

快速启动见 [06 运行与验证](06-运行与验证.md)，实际完成的测试结果见 [V0.1 验证记录](V0.1-验证记录.md)。本手册中的操作步骤不表示已经执行恢复演练或生产部署。

## 1. 接管前先确认什么

当前服务为 PostgreSQL 16.4、Java 后端、Nginx 托管的 React 前端。Compose 项目名固定为 guoxin-assistant；数据卷为 guoxin-assistant_postgres-data。修改项目名会创建另一组容器和卷，不能把新空库误认为数据丢失。

| 入口 | 地址与用途 |
| --- | --- |
| 工作台 | http://localhost:5173 |
| 后端健康 | http://localhost:8080/actuator/health |
| 数据库 | 127.0.0.1:55432；容器内 postgres:5432 |
| 演示账号 | DEMO001／DEMO002／DEMO003，密码 Demo@123，仅供模拟环境 |
| 数据库表 | gxa_* 为会话、任务和事件；gx_biz_* 为模拟业务和幂等回执 |

端口绑定 127.0.0.1，当前配置面向本机模拟与试点。首次启动幂等创建演示资料，后续重启保留办理状态。当前没有生产 SSO、完整管理权限体系或横向扩容支持；同库只启动一个后端执行器。后续接入真实系统时替换业务适配器，不复用演示密码和假审批路由。

## 2. 新机器准备

1. 安装 Git、Docker Desktop，启用 Linux containers／WSL 2 backend。Windows 安装可能需要管理员确认；若系统明确要求重启，先保存工作后手动重启。项目脚本不自动重启系统。
2. 验证 `docker version` 同时返回 Client 与 Server，并验证 `docker compose version`。仅有 CLI 版本不表示引擎已启动。
3. 取得完整源码、capabilities、prompts、deploy、compose.yaml 和锁文件。不要把 .env、数据库备份、会话日志或本机 .runtime 缓存提交到 Git。
4. 容器源码构建只要求 Docker 和网络。选择宿主 prebuilt 构建时，额外安装 Java 21、Maven 3.9+、Node 24 和 npm；必须用 `mvn -version` 检查实际 Java 版本，不能只看 `java -version`。
5. 按下一节设置模型及数据库配置，再运行源码构建或 prebuilt 路径。

本仓库 scripts/install-docker.ps1 是本机安装辅助脚本，固定校验 Docker 4.49.0 和 WSL 3.0.5 官方安装包的 SHA256。它要求安装包已位于 D:\GuoxinAssistantRuntime\installers，并不是通用联网下载器。新机可直接按 [Docker 官方 Windows 安装说明](https://docs.docker.com/desktop/setup/install/windows-install/)安装适用版本；升级 Docker 后重新验证项目，不盲目沿用旧安装包。

当前机器的 C 盘用户 AppData 存在重定向，导致文件原子重命名报跨盘错误。scripts/docker-env.ps1 将 Docker 当前进程及其子进程的配置、临时文件、CLI 配置隔离到 D:\GuoxinAssistantRuntime\Docker，不修改 User/Machine 环境，也不移动原有用户文件。正常新机器不必复制这项特殊目录设置；若复用脚本，先检查磁盘与路径是否适用。

## 3. 配置变量与密钥

首次本地配置可以复制模板；已有 .env 时不要覆盖：

```powershell
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
```

| 变量 | 默认与作用 |
| --- | --- |
| QWEN_API_KEY | 生成模型密钥；也可使用当前终端的 DASHSCOPE_API_KEY |
| QWEN_BASE_URL | https://dashscope.aliyuncs.com/compatible-mode/v1，按实际地域调整 |
| QWEN_MODEL | qwen-plus，按账号开通权限调整 |
| AGENT_MODEL_MODE | qwen；test 仅供显式测试，不能作为真实模型验收 |
| DATABASE_PASSWORD | 模板为 guoxin-local-demo，仅适用本机模拟环境 |

优先通过现有环境注入密钥；若用 .env，本地妥善保存，不能贴入日志、文档或截图。不要输出完整 `docker compose config` 或 `docker inspect` 容器环境，它们会展开密钥；检查 Compose 语法使用 `docker compose config --quiet`。

更换 Key、模型、地域后需重建后端容器以加载环境，单纯 `docker compose restart backend` 不会更新容器环境：

```powershell
. .\scripts\docker-env.ps1
docker compose up -d --no-deps --force-recreate --no-build backend
```

已有数据卷的 POSTGRES_PASSWORD 不会因为修改 .env 就自动改变数据库账号密码。需要明确执行数据库密码轮换并同步后端连接配置，不能通过删除卷来解决认证失败。当前会话 Key 不写入镜像构建参数或前端 bundle。

## 4. 已有机器日常启动与停止

当前特殊环境的推荐启动入口：

```powershell
.\scripts\start-docker.ps1
. .\scripts\docker-env.ps1
docker compose up -d --no-build
docker compose ps
Invoke-RestMethod 'http://localhost:8080/actuator/health'
```

`up --no-build` 仅使用已存在的项目镜像，适用于重启已有版本；镜像不存在时应选下一节构建流程，不能只启动一个空前端。若使用 prebuilt 的构建定义，也可显式带上两个 -f 文件。

```powershell
docker compose -f compose.yaml -f compose.prebuilt.yaml up -d --no-build
```

完成启动后，确认 postgres 为 healthy、后端健康为 UP、工作台可以登录，并查询一次本人待办。页面 HTTP 200 不能证明模型和业务工具已经可用。

```powershell
docker compose stop
# 已有容器再次启动
docker compose start
# 移除项目容器和网络，但保留命名卷
docker compose down
```

正常维护不要使用 `down -v`、`volume prune` 或删除 postgres-data；这些命令不属于本手册的日常流程。不要通过 Docker Desktop“恢复出厂设置”处理路径错误。

## 5. 两种构建路径

### 5.1 容器内从源码构建

```powershell
. .\scripts\docker-env.ps1
docker compose config --quiet
docker compose build backend frontend
docker compose up -d --no-build
```

也可运行 `.\scripts\start.ps1`，包含引擎检查与构建。源码 Dockerfile 会拉 Maven/Temurin、Node 和 Nginx 镜像，并下载 Maven/npm 依赖，适合网络正常的环境。保留 package-lock.json 和固定 Maven 依赖版本，构建日志应保存退出码与错误原因。

### 5.2 宿主构建产物、应用仍在 Docker 运行

适用于大型构建镜像下载受限，但本机已有 Java/Maven/Node 的情况：

```powershell
# 先确认 mvn -version 显示Java21；需要时仅在当前终端修正JAVA_HOME
mvn -version
mvn -s .mvn/settings.xml -f backend/pom.xml -B -ntp verify
Push-Location frontend
npm ci
npm run build
Pop-Location
.\scripts\prepare-prebuilt.ps1
. .\scripts\docker-env.ps1
docker compose -f compose.yaml -f compose.prebuilt.yaml build backend frontend
docker compose -f compose.yaml -f compose.prebuilt.yaml up -d --no-build
```

prepare-prebuilt.ps1 只收集当前 fat JAR、capabilities、prompts、dist 和 nginx.conf；不会编译源码，也不能证明 target/dist 与源码一致。修改源码后先重新构建并完成测试，再准备产物。必要时使用新的 Git worktree 或全新产物目录，防止旧文件残留；记录源代码版本和 JAR/dist 哈希。

单独修改后端时重新打包 JAR 并准备上下文，只重建 backend；单独修改前端时重新生成 dist，只重建 frontend。修改 Skill/Prompt 也需要将对应文件重新打入镜像，不能只刷新浏览器。

## 6. 验证与测试分层

### 6.1 默认后端测试与真实 PostgreSQL

```powershell
. .\scripts\docker-env.ps1
docker compose up -d postgres
docker compose --profile verify run --rm verify
```

verify 服务连接 Compose 内部 PostgreSQL，执行 Maven verify；真实 Qwen 用例默认跳过。数据库测试使用随机隔离 schema，不修改演示业务表；必须看测试汇总，区分通过与跳过。测试日志、Surefire XML 位于对应模块 target/surefire-reports。

已有宿主 Maven 缓存时，可用宿主运行测试并连接 Docker 数据库，仍不启动宿主数据库或应用进程：

```powershell
$env:PG_TEST_URL = 'jdbc:postgresql://127.0.0.1:55432/guoxin'
$env:PG_TEST_USER = 'guoxin'
# 与Compose启动时使用的值一致；此处不打印密码
$env:PG_TEST_PASSWORD = if ($env:DATABASE_PASSWORD) { $env:DATABASE_PASSWORD } else { 'guoxin-local-demo' }
# 使用自定义.env密码而非模板默认值时，须先将正确值载入当前环境，不能误用默认值
mvn -s .mvn/settings.xml -f backend/pom.xml -pl assistant-business-mock -am -B -ntp test
```

PG_TEST_URL 未设置时，这些数据库用例会跳过；不能将跳过报告为真实数据库测试通过。当前业务模块的真实 PG 验证结果为 11 项全部通过，后续新增用例以当次报告为准。

### 6.2 显式真实 Qwen 测试

```powershell
docker compose --profile verify run --rm verify mvn -s ../.mvn/settings.xml -B -ntp -pl assistant-agent -am -Dtest=QwenLiveTest -Dsurefire.failIfNoSpecifiedTests=false -Dagent.live-test=true test
```

该命令真实调用供应方并产生 API 用量，验证只读工具选择、工具结果回传及流式文字，不等于完整业务闭环验收。当前 verify 服务向容器注入 QWEN_API_KEY；本机只有 DASHSCOPE_API_KEY 时先设置当前终端的 QWEN_API_KEY 或使用 .env，避免验证容器拿不到 Key。不要把密钥写到命令参数中。

### 6.3 浏览器组件与真实闭环

浏览器测试要求已运行 Docker 工作台，不会自动启动本机 Vite。配置使用 Microsoft Edge；新机需有 Edge 或按 Playwright 文档配置对应浏览器。

```powershell
Push-Location frontend
npm ci
# API桩下的组件交互测试
npx playwright test tests/workbench.spec.ts
# 真实登录/对话/提单/审核，会写入模拟业务数据库，且qwen模式下产生模型用量
$env:RUN_LIVE_E2E = '1'
npx playwright test tests/live-workbench.spec.ts
Remove-Item Env:RUN_LIVE_E2E
Pop-Location
```

真实闭环测试只针对 local-demo 或专门测试环境运行，不能对真实企业审批系统直接执行。证照存在在途借用申请时再次提交会被业务规则阻止，这是需要检查的状态；不要清空库来追求绿灯。重新运行写入用例应使用独立测试数据或经过业务流程处理前次申请。

## 7. 修改代码到部署的完整步骤

1. 记录当前 Git 版本、镜像 ID、数据库版本与待执行任务；开新分支并明确本次修改范围。
2. 若涉及业务状态、表结构、能力规则或模型行为，先补相应验收场景。业务权限在后端实现，不能只调整 Prompt 或前端按钮。
3. 按模块修改：application/domain 为契约，agent 为编排与模型，business-mock 为模拟业务，infrastructure 为持久化，boot 为 API/身份，frontend 为工作台组件。
4. 运行默认后端测试、真实 PG 测试和前端构建；影响模型或交互时追加真实 Qwen及相关浏览器用例，记录实际模型、配置与结果。
5. 使用 backup-db.ps1 备份数据库；给当前应用镜像打保留标签，记录发布源版本及产物哈希。
6. 构建新镜像。需要避免新旧执行器并存时，先停止旧 backend，再启动新 backend；不横向加实例。
7. 启动后检查健康、日志、登录、只读待办查询，再验证受控业务流程；检查旧任务、草稿和确认恢复是否兼容。
8. 记录发布结果、数据迁移、已知限制及回滚条件，确认稳定后再按约定保留周期清理旧构建缓存。备份不随镜像缓存一起清理。

改变 API/组件 Schema 时前后端一起升级；改变确认内容、元数据或审核范围时应使旧确认失效。已有业务写入不能靠回放旧图或切换镜像撤销。

## 8. 数据库备份

```powershell
.\scripts\backup-db.ps1
# 或明确指定受控备份目录
.\scripts\backup-db.ps1 -OutputDirectory 'D:\GuoxinAssistantRuntime\backups'
```

脚本在运行中的 PostgreSQL 容器内用 pg_dump custom 格式取得一致性快照，先写容器临时文件并验证 archive 列表，再通过 docker cp 原样复制，生成 SHA256 文件，最后仅清理本次容器临时文件。不会删除卷或覆盖既有备份。不要用 PowerShell 的 `>` 或文本管道承接二进制 dump。

备份包含对话、草稿、个人业务和操作记录，需要控制存取。备份目录必须独立于工作区和 Docker 数据卷，并另外复制到受控的独立存储，不能将“在同一块磁盘有一份备份”当作灾备完成。

数据库备份不包含 .env、角色全局定义、镜像或源码。交接时分别记录数据库账号/权限的受控配置、密钥管理位置、Git 版本、应用镜像标签和 PostgreSQL版本。Archive 列表可读与 SHA256 正确仍不等于已经验证可恢复，需要独立空库演练。

## 9. 恢复演练：只恢复到新的空库

以下为人工维护步骤，交付时没有执行恢复。示例始终创建独立新库，不覆盖 guoxin，不带 --clean、不删除原卷。仅使用可信来源的备份。

```powershell
. .\scripts\docker-env.ps1
$backupFile = 'D:\GuoxinAssistantRuntime\backups\替换为实际备份文件.dump'
# 先将Get-FileHash结果与同名.sha256记录比较
Get-FileHash -LiteralPath $backupFile -Algorithm SHA256
$restoreDatabase = 'guoxin_restore_' + [DateTime]::UtcNow.ToString('yyyyMMdd_HHmmss')
$postgresContainer = (docker compose ps -q postgres).Trim()
$restoreArchive = '/tmp/guoxin-restore-' + [Guid]::NewGuid().ToString('N') + '.dump'
docker cp $backupFile ($postgresContainer + ':' + $restoreArchive)
if ($LASTEXITCODE -ne 0) { throw '复制备份失败，停止恢复' }
docker compose exec -T postgres createdb -U guoxin --template=template0 $restoreDatabase
if ($LASTEXITCODE -ne 0) { throw '新库创建失败，停止恢复；不得覆盖已有库' }
docker compose exec -T postgres pg_restore -U guoxin --dbname=$restoreDatabase --no-owner --no-privileges --single-transaction --exit-on-error $restoreArchive
if ($LASTEXITCODE -ne 0) { throw '恢复失败，保留新库与日志用于排查，不切换应用' }
docker compose exec -T postgres psql -U guoxin -d $restoreDatabase -c '\dt'
```

恢复后抽查关键表行数、单据/流程关联、草稿、审批记录及操作回执。正式切换前停止旧后端，评估恢复出的未完成命令是否允许继续执行，并核对外部业务系统实际状态；恢复旧数据库不会撤销外部已经完成的审批。

验证通过后，可以创建只改变后端 DATABASE_URL 的本地覆盖文件，将库名指向新库，再用该覆盖文件启动后端。保留原 guoxin 库不动；不同时启动连接新旧库的业务执行器办理同一真实任务。切换细节应写入本次维护记录，后续每次启动都使用相同覆盖文件，防止又连接回旧库。

不将已恢复的新库直接当作无状态回滚：恢复点之后的新消息、审批和业务提交可能不存在，需要对账。PostgreSQL 跨大版本升级单独制定并演练，不直接修改 image 主版本后复用原数据目录。

## 10. 应用镜像回滚与数据库迁移

升级前保留当前已运行镜像，而不是在失败后再找“上一个 latest”：

```powershell
. .\scripts\docker-env.ps1
$releaseStamp = [DateTime]::UtcNow.ToString('yyyyMMdd-HHmmss')
docker image tag guoxin-assistant-backend:latest ('guoxin-assistant-backend:before-' + $releaseStamp)
docker image tag guoxin-assistant-frontend:latest ('guoxin-assistant-frontend:before-' + $releaseStamp)
docker compose images
```

如镜像名与当前环境不同，以 `docker compose images` 的结果为准。记录这两个实际标签；回滚时写入独立覆盖文件：

```yaml
# .runtime/rollback.yaml：把示例标签替换为上一步实际记录值
services:
  backend:
    image: guoxin-assistant-backend:before-实际时间
  frontend:
    image: guoxin-assistant-frontend:before-实际时间
```

```powershell
docker compose stop backend
docker compose -f compose.yaml -f .runtime/rollback.yaml up -d --no-build --no-deps backend frontend
```

--no-build 防止覆盖文件中保留的 build 定义重新构建错误版本。回滚后检查健康和旧任务兼容性；后续启动继续带 rollback.yaml，或将发布配置明确调整到对应版本。

当前表初始化主要为幂等建表 SQL，不是完整的数据库迁移管理系统。新增列/索引应提供有版本、可重复检查的迁移脚本，先在隔离库验证，再备份、停业务写入并迁移。优先采用向后兼容的增量变更；删除/重命名字段、改变任务状态 JSON 时，旧镜像可能无法读取新数据，此时不能只回滚镜像。不得直接使用恢复备份覆盖演示库作为普通版本回退。

## 11. 排障清单

| 现象 | 检查与处理 |
| --- | --- |
| Docker pipe不存在 | 先运行start-docker.ps1，确认Server版本；查看D盘Local/Docker/log/host日志。不要只检查CLI版本 |
| settings-store.json重命名跨盘错误 | 确认通过项目隔离环境启动；本机C用户目录存在重定向。不要恢复出厂，不改全局APPDATA |
| daemon退出后再次双击桌面图标又报错 | 桌面快捷方式没有项目进程环境，应使用scripts/start-docker.ps1 |
| 镜像认证解析到异常IPv6/地址 | 系统DNS与真实结果不一致；本机已有系统代理，Python urllib可读取。只在相关进程传递代理，不写全局hosts/DNS，不使用不可信镜像源 |
| 镜像层大文件截断/SSL EOF | 保留校验缓存重试；scripts/pull_official_image.py从官方认证/registry/CDN获取并校验digest及大小，不能关闭TLS验证或接受不匹配层 |
| PG密码认证失败 | 核对当前数据卷初始化密码与后端配置，修改.env不能重置旧账号；不要删卷 |
| 后端起不来且报执行器已运行 | 单实例advisory lock生效，先停止旧backend；不得用第二实例强行抢同库任务 |
| 模型401/403/404 | 核对Key、地域、base URL、模型开通权限；不能切到test冒充修复 |
| 参数缺失/元数据错误 | 查看工具fieldErrors与版本，回到资料补齐；不是不断网络重试 |
| 提交超时、状态未知 | 按operationId查回执，保留原幂等键；不能换新编号重提 |
| 确认409或旧卡片不可点 | 任务/单据版本或确认范围已变化，刷新并重新生成预览 |
| 改代码却没生效 | 检查实际镜像、源码版本及prebuilt产物是否重新生成，不能只restart旧镜像 |

```powershell
docker compose logs --tail 150 backend
docker compose logs --tail 100 postgres
docker compose logs --tail 100 frontend
docker compose ps
```

日志可能包含个人业务摘要，提供给维护者时按任务编号/traceId截取必要部分，避免公开完整环境或密钥。

官方OCI下载备用示例（仅当普通pull失败且确需使用）：

```powershell
. .\scripts\docker-env.ps1
python scripts/pull_official_image.py eclipse-temurin:21-jre-alpine nginx:1.28-alpine --workers 8
```

只针对本项目所需官方镜像，保留脚本输出的manifest/config/layer校验结果；下载缓存只是安装辅助，不是运行时数据库。受限网络中拉取完成后也要验证真实容器健康和模型访问。

## 12. 交接记录最小清单

- 源码版本、未提交变更、发布镜像标签/ID、JAR与dist来源。
- 配置变量名称及密钥存放位置，不记录密钥值。
- Compose文件组合、端口、数据库与卷名、特殊Docker启动方式。
- 数据库迁移版本、备份文件/校验值/时间、独立恢复演练结果。
- 后端、真实PG、真实Qwen、组件浏览器和真实业务浏览器用例的分别结果。
- 在途申请、失败任务、未知结果操作、已知限制及恢复负责人。
