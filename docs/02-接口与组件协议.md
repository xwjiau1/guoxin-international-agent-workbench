# 02 接口与组件协议

## 1. 通用约定

工作台前缀 /api/v1；内部模拟业务前缀 /internal/business/v1。后者仅供服务端适配器调用，不直接对浏览器开放。API 字段使用 camelCase，ID 为服务端生成的 UUID，业务编号单独提供。时间用带偏移的 ISO 8601，数据库存 UTC；日期用 YYYY-MM-DD，解释用户相对日期时使用 Asia/Shanghai。

统一响应：成功为 {code:"OK",data:{...},traceId:"..."}；失败为 {code,category,message,fieldErrors:[],traceId,recoveryAction}。fieldErrors 每项为 {path,code,message,allowedValues?}，recoveryAction 为 COLLECT_FIELDS/RELOGIN/REFRESH_PREVIEW/RETRY_LATER/RECONCILE/NONE。

HTTP 状态：400 无法解析；401 未登录；403 当前用户无业务权限；404 资源不存在或非本人资源；409 版本/状态/幂等冲突；422 参数或业务校验不通过；429 限流；503 暂时不可用。异步任务已受理返回 202，之后的业务失败通过任务与事件查询，不能因为已返回 202 就认定办理成功。

分页使用 cursor/limit，默认 20、最大 100；同一查询按时间和 ID 稳定排序。所有列表服务端强制添加当前用户范围，禁止前端传 actorId/assigneeId 改变查询人。

认证采用服务端 session + HttpOnly Cookie，同源请求并启用 CSRF 校验。CSRF token 通过登录结果或 GET /me 获取，用于后续修改请求；登录本身校验 Origin。演示登录只在 local-demo profile 开启，支持固定账号密码，不接受任意 userId 免密切换；真实 SSO 后续替换认证适配器。Session 不进入模型上下文。无权资源统一 404，接口不泄露其是否存在。

## 2. 工作台 API

机器可读草案见 [OpenAPI](contracts/workbench.openapi.json)，本节补充异步语义与交互规则。

| 方法与路径 | 请求关键字段 | 结果/说明 |
| --- | --- | --- |
| POST /auth/demo-login | username,password | 建 session；仅演示环境 |
| POST /auth/logout | CSRF header | 清 session |
| GET /me | 无 | 本人资料和可用能力，不返回凭证 |
| GET /conversations | cursor,limit | 本人会话列表 |
| POST /conversations | title? | 新会话 |
| GET /conversations/{conversationId} | 无 | 会话、activeTaskId、lastEventId |
| GET /conversations/{conversationId}/messages | cursor,limit | 历史消息与持久化组件 |
| POST /conversations/{conversationId}/messages | clientMessageId,text,taskId? | 202：messageId、runId；必要时 taskId 稍后通过事件返回 |
| GET /conversations/{conversationId}/events | afterEventId? | SSE，支持 Last-Event-ID |
| GET /tasks/{taskId} | 无 | 任务状态、版本、草稿、可恢复入口和当前组件 |
| POST /tasks/{taskId}/actions | actionId,type,expectedTaskVersion,payload | 202：runId，统一处理组件交互 |
| GET /tasks/{taskId}/trace | cursor,limit | 节点、模型、工具、重试与业务回执摘要 |
| GET /drafts | cursor,limit | 本人草稿 |
| GET /drafts/{draftId} | 无 | 草稿、字段与版本 |

消息 text 默认最大 8000 字符；超过限制明确返回 422，不截断。重复 clientMessageId + 相同内容返回原受理结果；相同 ID 不同内容返回 409。actionId 使用相同规则。

## 3. 组件动作

type 枚举：PROVIDE_FIELDS、UPDATE_REVIEW、CONFIRM、SAVE_DRAFT、RESUME、PAUSE、CANCEL、RETRY_FAILED。

| 动作 | payload | 服务端行为 |
| --- | --- | --- |
| PROVIDE_FIELDS | componentId,componentVersion,values | 校验可编辑字段后合并，重新校验任务 |
| UPDATE_REVIEW | componentId,componentVersion,selectedTodoIds,decision,comment | 校验候选集合与状态，生成新预览及 confirmationId |
| CONFIRM | confirmationId | 只接受服务端保存的范围，不接受临时附加字段或 ID |
| SAVE_DRAFT | componentId?,componentVersion? | 保存当前任务字段；若用户有未保存编辑须先 PROVIDE_FIELDS |
| RESUME | 空 | 恢复当前任务；补充或修改可走后续动作 |
| PAUSE / CANCEL | 空 | 停止新步骤；已发出的写入继续核实，不假称已撤销 |
| RETRY_FAILED | sourceOperationId,itemIds? | 仅处理已确认范围内可恢复失败项，不重做成功项 |

每个动作校验 expectedTaskVersion，避免多标签页覆盖；返回当前版本或 409。UPDATE_REVIEW 只从既有候选项中选择，扩大范围必须重新查询。大列表确认以服务端快照为准，不能把“全选”解释成点击时动态扩大的集合。

用户通过自然语言修改也走同一应用用例。明确的“确认提交”仅在当前任务唯一、存在有效预览、内容与范围未变时绑定该确认；有歧义则询问。模型不能返回一个伪造的 confirmationId 来绕过校验。

## 4. SSE 事件

先 POST 持久化消息并返回 202，再订阅 GET SSE；避免把 POST 请求长连接与任务生命周期绑定。建立 SSE 前已发生的事件从持久层补发。

```text
id: 128
event: component.upsert
data: {"schemaVersion":"1.0","eventId":"128","conversationId":"...","taskId":"...","runId":"...","traceId":"...","occurredAt":"2026-11-11T19:00:00+08:00","payload":{"componentId":"...","type":"FORM_PREVIEW","version":3,"status":"ACTIVE","data":{}}}
```

eventId 在会话内单调递增，字符串传输；客户端按 eventId 去重。Last-Event-ID 与 afterEventId 同时存在时须相同，否则 400。历史游标超出保留范围返回 409 EVENTS_EXPIRED，客户端获取会话和任务快照后继续订阅。

事件种类：run.accepted、task.updated、message.delta、message.completed、message.reset、component.upsert、tool.started、tool.completed、retry.scheduled、operation.updated、run.finished、error。

文本增量按 messageId + chunkIndex 合并；同一组件按 componentId + version 更新。所有前端可恢复的事件持久化，文本增量可按短时间窗口合并入库；message.completed 保存最终全文。重启时可用最终消息或 message.reset 修复未完成的文本展示。

15 秒注释心跳不存储；断线重连仅重订阅，绝不重新 POST 原业务操作。run.finished 表示本轮结束，不等于任务或审批流程完成。批量结果可以在同一任务内持续更新。

## 5. 组件结构与交互

统一结构：componentId、taskId、type、version、status、data、allowedActions。status 为 ACTIVE/SUPERSEDED/CONSUMED/EXPIRED。前端只渲染已注册组件，不执行服务端或模型返回的任意 HTML/JS。

| 组件 type | data 必要内容 | 交互 |
| --- | --- | --- |
| FIELD_COLLECTION | schemaVersion,fields,values,fieldErrors | 补充、保存草稿、暂停 |
| FORM_PREVIEW | formType,metadataVersion,fields,summary,confirmationId,expiresAt | 修改、保存草稿、确认提交 |
| TODO_SELECTION | filters,dateInterpretation,totalCount,items,selectedIds,decision,comment | 筛选、选中/排除、修改意见 |
| APPROVAL_PREVIEW | snapshotId,items,decision,comment,confirmationId,expiresAt | 返回修改、确认审核 |
| BUSINESS_RECEIPT | operationId,businessNo,processNo,businessStatus,items | 查看进度、按允许项重试 |
| TASK_CHOOSER | tasks | 选择继续的任务 |
| RECOVERY_NOTICE | errorCode,reason,recoveryAction,operationId? | 重试或核实结果 |

FIELD_COLLECTION.fields 项包含 key、label、type、required、editable、source、options、validation；UI 只支持已约定的 string/date/enum/decimal/text 类型和简单条件规则，不执行后端传来的任意表达式。

审批预览列出单据类型、编号、申请人、到达日期、摘要、当前状态和版本；敏感详情按审批所需最小范围展示。默认单次最多确认 100 项，更大范围分批并分别确认；禁止把页面当前 20 项静默当成全部结果。

页面布局：左侧会话和草稿入口，中间聊天及组件，右侧任务进度与可折叠执行记录。业务结果由业务回执组件确定，模型总结与其冲突时以回执为准。卡片刷新后保留已失效/已执行提示，不能再次点击旧卡片。

## 6. 业务接口与工具目录

这些是服务端内部契约，V0.1 以 Java 端口 + 模拟实现调用；同进程不额外绕 HTTP。接口文档保留 HTTP 映射用于 V0.2 发布和未来真实适配。内部身份只由可信适配器传播，不能透传模型提交的身份。

| 内部业务路径 | Tool 名称或执行节点 | 主要参数 |
| --- | --- | --- |
| GET /profile/me | profile_get_self | 无 |
| GET /forms/{formType}/schema | form_get_schema | formType |
| GET /credentials/mine | credential_list_mine | credentialType? |
| POST /forms/validate | form_validate | formType,metadataVersion,mode,values |
| POST /drafts | draft_save | draftId?,expectedVersion?,formType,values；执行上下文注入幂等键 |
| GET /drafts/{draftId} | draft_get | draftId |
| POST /applications/submit | submit_application 节点 | 服务端确认快照、operationId |
| GET /applications/{applicationId} | application_get | applicationId |
| POST /todos/search | todo_search | types,dateField,from,to,status,keyword,cursor,limit |
| POST /todos/statistics | todo_statistics | 与 search 同一过滤对象，统计由数据库完成 |
| POST /todos/review | review_todo 节点 | 单个 todoId,expectedVersion,decision,comment,operationId |
| GET /operations/{operationId} | operation_get 节点 | operationId |

form_validate 的 mode 为 DRAFT/SUBMIT；DRAFT 不强制提交必填项，仍校验已填值。应用提交接口在模拟底座一个事务内创建单据、流程和首个待办，不采用模型分别调用三个接口拼接。

关键词仅作业务查询条件：先把口语单据名映射到合法枚举，再使用参数化筛选/全文查询。禁止生成任意 SQL。模型描述的统计不作为数据来源。

## 7. ToolResult 与错误协议

```json
{
  "success": false,
  "code": "VALIDATION_REQUIRED",
  "category": "VALIDATION",
  "message": "请补充归还日期",
  "fieldErrors": [{"path":"returnDate","code":"REQUIRED","message":"归还日期必填"}],
  "recoveryAction": "COLLECT_FIELDS",
  "operationId": null,
  "businessStatus": null,
  "data": null
}
```

工具执行事件额外记录 attempt、耗时、底层错误及脱敏摘要。仅向模型返回其完成任务所需的结构化信息，凭证、SQL、堆栈和内部地址不进入工具结果。

工具策略按工具名固定：READ_ONLY、DRAFT_WRITE、CONFIRMED_WRITE；模型生成的 retryable 或 safetyLevel 字段不参与服务端决策。写入最终回执可由确定性模板展示，模型不可用时仍能交付真实结果。
